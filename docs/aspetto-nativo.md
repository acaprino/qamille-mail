# Aspetto nativo dell'app desktop

Qamille gira dentro WebView2: senza accorgimenti si comporta come una pagina web
(testo selezionabile ovunque, F5 ricarica, tasto destro con "Indietro" e "Stampa",
finestra bianca all'avvio col tema scuro). Questa guida elenca le regole che lo
fanno sembrare un'app Windows e come non romperle.

Origine: [8 tips for creating a native look and feel in Tauri applications](https://dev.to/akr/8-tips-for-creating-a-native-look-and-feel-in-tauri-applications-3loe),
adattato a Tauri 2 su Windows. Il consiglio solo macOS sul beep dei tasti non si applica;
lo scorrimento oltre il bordo sì: un touchpad di precisione o un touchscreen lo fanno anche
su Windows (regola 4).

**Controllo automatico:** `node tests/native-feel.mjs` (da `desktop/`, o
`npm run test:native-feel`). Gira in meno di un secondo, senza build. Va lanciato
dopo ogni modifica a CSS globali, tema, finestre o `src-tauri/src/`.

| 23 | Ogni finestra mostra solo la pagina dell'app: una navigazione verso un altro indirizzo viene rifiutata e un link web o mailto si apre nel browser di sistema (solo dalla principale). Un frame (l'iframe del messaggio) mostra solo il suo documento (`about:srcdoc`) o un frame vuoto (`about:blank`): un link dentro un messaggio non lo porta altrove, e nessun frame carica la pagina dell'app o il web. Un link che sfuggisse alla pagina non carica comunque il web, ma il frame perde il suo documento: in un frame di prova sull'exe (WebView2 157) la fuga l'ha chiusa la CSP (`frame-src 'none'`), con una pagina d'errore vuota (`chrome-error://chromewebdata/`); il rifiuto nativo del frame (`FrameNavigationStarting`) non è stato osservato in azione, perché la CSP agisce prima o al suo posto. Un frame `srcdoc` non ha un indirizzo suo: un link a una parte del messaggio (`#…`) lo risolverebbe contro quello dell'app e avvierebbe una navigazione, che il lato nativo rifiuta, quindi se ne occupa la pagina (`MessageHtml.tsx` annulla il clic e scorre fino alla parte).
